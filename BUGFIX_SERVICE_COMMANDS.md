# Исправление бага: служебные кнопки как логин/пароль

## Реальная причина бага

Проблема вызвана **запуском нескольких экземпляров бота с одним токеном**. При этом:
1. Один экземпляр (возможно старый) обрабатывает апдейты и НЕ распознаёт служебные кнопки
2. Другой экземпляр пытается получить апдейты и получает ошибку `409 Conflict`
3. Логи не показывают сообщения о служебных командах, потому что обрабатывается не этот файл

## Изменения в telegram_bot/bot.py

### 1. Single-instance lock (строки 5024-5130)

**Функции:**
- `acquire_instance_lock()` - проверяет и создаёт lock-файл
- `release_instance_lock()` - удаляет lock-файл при выходе

**Механизм:**
- Создаёт файл `bot.lock` в директории бота
- Записывает: PID, instance_id (UUID), путь к скрипту, timestamp
- При втором запуске:
  - Проверяет существование lock-файла
  - Читает PID и проверяет, жив ли процесс
  - Если процесс жив — выводит подробную ошибку и завершается
  - Если процесс неактивен — удаляет устаревший lock-файл

**В main() (строки 5137-5141, 5190-5192):**
- Проверка lock на старте
- Выход с ошибкой если другой экземпляр запущен
- `finally` блок гарантированно освобождает lock при любом завершении

### 2. Улучшенная распознавание служебных команд

**SERVICE_COMMAND_PATTERNS (строки 406-423):**
- Добавлены дополнительные паттерны для robust matching
- Поддерживает варианты: "ru en", "ruen", "ru/en", "🌐 ru/en"
- Поддерживает: "restart bot", "перезапуск бота" и вариации

**normalize_service_command() (строки 424-447):**
- Улучшено логирование для отладки
- Более надёжная нормализация текста
- Логирует обнаруженные команды и неудачные попытки

### 3. Жёсткая защита в handle_message() (строки 4003-4074)

**Добавлено:**
- Логирование ВСЕХ входящих текстовых сообщений (строка 4020)
- Раннее обнаружение служебных команд (строки 4022-4074)
- Явная проверка `if cmd_type is not None:` (строка 4026)
- Предупреждающее логирование при блокировке (строка 4027)
- Обязательный `return` после обработки служебной команды
- Отладочное логирование для обычных сообщений (строка 4077)

**Гарантии:**
- Служебные команды обрабатываются ДО любых state-веток
- Текст служебных кнопок никогда не попадает в `context.user_data['username']`
- Текст служебных кнопок никогда не попадает в `login()`
- Явное разделение путей обработки

## Как проверить исправление

### 1. Запущен только один экземпляр
```bash
# Запустите бота первый раз
python telegram_bot/bot.py

# В логах увидите:
# 🔒 Проверка блокировки экземпляра...
# ✅ Lock-файл создан: .../bot.lock

# Попробуйте запустить второй раз (другое окно терминала)
python telegram_bot/bot.py

# В логах увидите:
# ❌ ОШИБКА: Бот уже запущен!
# Instance ID текущего: ...
# Instance ID запущенного: ...
# PID текущего процесса: ...
# PID запущенного процесса: ...
#   РЕШЕНИЕ:
#   Остановите процесс с PID ...
#   Или удалите lock-файл: .../bot.lock
```

### 2. Логи показывают правильную обработку
```bash
# При нажатии "🌐 RU/EN" в WAITING_FOR_LOGIN:
# 📩 Текстовое сообщение от chat_id=..., state=WAITING_FOR_LOGIN: '🌐 RU/EN'
# 🚫 Блокируем служебную команду cmd_type=language: текст '🌐 RU/EN' не будет записан как логин/пароль
# 🌐 Служебная команда language от chat_id=...
# 📝 Обновление экрана для состояния WAITING_FOR_LOGIN

# При вводе реального логина:
# 📩 Текстовое сообщение от chat_id=..., state=WAITING_FOR_LOGIN: 'myusername'
# ✓ Сообщение не является служебной командой: 'myusername'
```

### 3. Нет ошибок Conflict
После запуска бота:
- Проверьте лог - не должно быть `409 Conflict`
- Проверьте, что только один процесс с этим токеном

## Диагностика при проблемах

### Если бот всё ещё принимает кнопки как логин:
1. Остановите все процессы бота
2. Удалите файл `bot.lock`:
   ```bash
   rm telegram_bot/bot.lock
   ```
3. Запустите бот заново
4. Проверьте логи - должны видеть instance ID и PID

### Если несколько lock-файлов:
Найдите и удалите старые lock-файлы:
```bash
find . -name "bot.lock" -type f
```

### Если не знаете, какой процесс запущен:
Windows:
```powershell
tasklist | findstr python
```

Linux/Mac:
```bash
ps aux | grep python | grep bot
```
